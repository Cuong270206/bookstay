Lớp 4 — ACCEPTANCE CRITERIA (Given-When-Then)

4.1 Booking Flow

◇ DECISION: Guest chọn ngày không trống
Happy: Guest chọn 2 đêm cuối tuần → hiện giá = base × nights × 1.2 (weekend rate)
Unhappy: Guest chọn ngày đã booked → hiện toast "Ngày này không trống"

◇ DECISION: Thanh toán VNPay thành công
Happy: VNPay return?vnp_ResponseCode=00 → Booking status = CONFIRMED → redirect /success
Unhappy: VNPay return?vnp_ResponseCode≠00 → Booking status = PAYMENT_FAILED → retry option

◇ DECISION: Booking tạo → calendar bị block ngay
Happy: Booking confirmed → Calendar slot marked as booked → Host thấy ngay
Unhappy: 2 guest đặt cùng slot → second guest → show "Ngày không trống"

◇ DECISION: VNPay timeout (15 phút không callback)
Given: Guest redirect sang VNPay, đóng tab trước callback
When: Cron 5 phút kiểm tra
Then: PENDING_PAYMENT > 15 phút → auto cancel booking → slot unlock

◇ DECISION: Lock hết 20 phút mà chưa thanh toán
Given: Guest chọn date → lock 20 phút bắt đầu
When: Guest không thanh toán trong 20 phút
Then: Slot unlock → guest phải chọn lại date

◇ DECISION: Cancel trước 7 ngày
Given: Booking confirmed, check-in trong 10 ngày
When: Guest click Cancel → confirm modal hiện "Hoàn 100%: 2,000,000 VND"
Then: Booking status = CANCELLED, refund = 100%, guest notified

◇ DECISION: Cancel 3-7 ngày
Given: Booking confirmed, check-in trong 5 ngày
When: Guest click Cancel
Then: Modal hiện "Hoàn 50%: 1,000,000 VND" → confirm → status = CANCELLED

◇ DECISION: Cancel < 3 ngày
Given: Booking confirmed, check-in trong 2 ngày
When: Guest click Cancel
Then: Modal hiện "Không hoàn tiền" → confirm → status = CANCELLED, no refund

◇ DECISION: Guest đã check-in, muốn hủy sớm
Given: Guest đã check-in Jan 10, dự định ở 5 đêm
When: Guest muốn hủy Jan 12 vì "homestay không như ảnh"
Then: 0% refund (sau check-in = no refund). Host confirm early checkout → COMPLETED
→ Guest vẫn ở 2 đêm → không refund

◇ DECISION: Checkout — auto hay manual
Given: Booking check-out Jan 15 12:00
When: 12:00 + 30 phút grace period pass
Then: Booking auto COMPLETED → trigger review notification + settlement cron

4.2 Host Listing Creation

◇ DECISION: Listing mới tạo
Happy: Host submit → status = PENDING_REVIEW → redirect to dashboard với banner "Đang chờ duyệt trong 24h"
Unhappy: Admin reject → status = REJECTED → reason shown → host edit & resubmit

◇ DECISION: Admin approve listing
Happy: Admin click Approve → status = PUBLISHED → visible to guests
Unhappy: Admin request edit → status = NEEDS_EDIT → host sees feedback → resubmit

◇ DECISION: Calendar conflict khi tạo booking
Given: Host đã block Jan 5-10 "Maintenance"
When: Guest đặt Jan 7-9
Then: Hiện toast "Ngày không trống" → guest chọn ngày khác

◇ DECISION: Host cố xóa listing có booking ACTIVE
Given: Listing có booking CONFIRMED Jan 20-25
When: Host click Delete
Then: Error modal "Không thể xóa: đang có booking active. Vui lòng chờ sau ngày 25/01"

◇ DECISION: 2 host cùng edit calendar
Given: Host A và Host B cùng mở calendar
When: Host A block Jan 10-15, Host B block Jan 12-18
Then: Second save → optimistic lock fail → "Calendar đang được chỉnh sửa bởi người khác. Refresh để xem thay đổi"

4.3 Chat

◇ DECISION: Guest gửi tin nhắn
Given: Guest ở trong booking đã confirmed
When: Guest type + send
Then: Message lưu DB → polling 5s → both sides thấy message

◇ DECISION: Host offline → guest gửi message
Given: Host offline (last_seen > 5 min)
When: Guest gửi message
Then: Message vẫn lưu → host thấy khi online → guest thấy "Đã gửi"

◇ DECISION: Guest gửi message sau booking CANCELLED
Given: Booking cancelled
When: Guest mở chat
Then: Chat read-only, hiện "Booking đã hủy"

4.4 Payment Settlement

◇ DECISION: Booking completed → settlement cho host
Given: Check-out date passed → booking COMPLETED
When: System cron chạy daily
Then: Tính: total - (total × 15%) = host payout → initiate VNPay settlement
→ Nếu host chưa có bank account → settlement FAIL → retry 3 lần → escalate Admin

◇ DECISION: Refund sau settlement
Given: Guest cancel, check-out passed, settlement đã chạy
When: Admin approve refund request
Then: Trừ vào settlement kỳ tiếp theo hoặc yêu cầu host chuyển lại

◇ DECISION: Host chưa complete bank account
Given: Host APPROVED nhưng chưa thêm bank account
When: Guest đặt homestay của host
Then: Booking vẫn được tạo → nhưng host nhận notification "Vui lòng thêm bank account để nhận thanh toán"
→ Settlement cron: skip nếu bank account invalid

4.5 Review

◇ DECISION: Guest không review sau checkout
Given: Booking COMPLETED Jan 15, guest không review
When: 24h sau checkout
Then: Gửi email/SMS reminder "Bạn có đánh giá chưa hoàn thành"
→ 14 ngày sau checkout: review form đóng → không review được nữa

◇ DECISION: Guest edit review
Given: Guest đã submit review
When: Trong vòng 48h
Then: Guest có thể edit review → cập nhật rating + text

◇ DECISION: Host flag review
Given: Host thấy review không đúng sự thật
When: Host click "Report" → nhập lý do
Then: Admin nhận complaint → review tạm ẩn → Admin decide remove/keep

4.6 Admin Actions

◇ DECISION: Admin suspend host có booking active
Given: Host có booking CONFIRMED Jan 20-25
When: Admin click Suspend Host
Then: Host suspended → listing ẩn search → booking Jan 20-25 vẫn hoàn tất
→ Host không nhận booking mới → sau Jan 25 → host có thể reactivate

◇ DECISION: Admin delete user (soft delete)
Given: Admin click Delete User
When: User đang có booking
Then: Soft delete → user marked SUSPENDED → booking history giữ nguyên
→ User không đăng nhập được → Admin có thể reactivate

🚩 RED FLAGS (Challenger Review — Đã fix)

1. VNPay Callback Race Condition [FIXED]
  • Lock duration = 20 phút (≥ VNPay timeout)
  • Polling /booking/:id/status mỗi 3s sau redirect, stop khi có callback HOẶC timeout 15 phút
  • Idempotency key trên VNPay request — retry không double charge
  • Cron backup: mỗi 5 phút check PENDING_PAYMENT > 15 phút → auto cancel
2. Calendar Overbooking [FIXED]
  • Temporary lock 20 phút khi guest chọn date range
  • Thanh toán thành công → confirm block → lock released
  • Conflict: RED overlay + toast "Ngày đã có booking"
  • 2 host edit calendar: optimistic lock với version field
3. Host Submit Listing → No Feedback Loop [FIXED]
  • Banner "Đang chờ duyệt trong 24h" trên dashboard
  • Email/SMS notification khi admin action
  • SLA: admin phải respond trong 24h
4. Chat Real-time [FIXED]
  • Polling 5s, đủ cho v1
  • last_message_at để sort, message mới nhất lên trên
  • "Đã gửi" indicator cho guest biết message đã được gửi
5. Host Decline sau Payment [FIXED]
  • Decline CHỈ khi booking status = PENDING_PAYMENT (trước payment)
  • Sau CONFIRMED: KHÔNG có decline → guest phải cancel theo policy
  • Booking SLA: nếu host không respond trong 24h → auto cancel + refund 100%
6. Delete Listing có Booking Active [FIXED]
  • Hard rule: KHÔNG cho delete listing có booking CONFIRMED/ACTIVE
  • Chỉ allow delete khi tất cả booking = COMPLETED/CANCELLED/REFUNDED
  • Soft delete: listing ẩn search nhưng guest đã book vẫn thấy trong history
  • Reviews của deleted listing hiển thị dưới "[Homestay đã xóa]"
7. Suspend User có Booking [FIXED]
  • Admin KHÔNG xóa user → chỉ SUSPEND (soft delete)
  • Suspended Guest: vẫn thấy booking history, KHÔNG tạo booking mới
  • Suspended Host: listing ẩn search, booking cũ vẫn hoàn tất, KHÔNG nhận booking mới
  • Settlement đã settle → giữ, pending → cancel
  • Reactivate: Admin action → restore all + notify user
8. Settlement khi chưa có Bank Account [FIXED]
  • Host phải complete bank account trước khi nhận booking
  • Settlement fail → Retry 3 lần trong 3 ngày → Notify host email/SMS
  • Sau 7 ngày fail → Escalate to Admin
  • Platform giữ tiền trong escrow, không dùng được
9. Guest không Review sau Checkout [FIXED]
  • Review KHÔNG bắt buộc → booking vẫn COMPLETED
  • Reminder: Email + In-app notification sau checkout 24h
